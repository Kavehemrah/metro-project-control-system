# چک‌لیست تست عملی Metro Project Control System

## پیش از اجرا
- برنامه را ببندید.
- از فایل `data/project.db` یک نسخه پشتیبان خارج از پوشه پروژه بگیرید.
- شاخه کاری را به‌روز کنید و آزمون‌های خودکار را اجرا کنید:
  ```powershell
  git status
  git branch --show-current
  git pull origin feature/activity-cost-resource-planning
  python -m pytest -q
  python main.py
  ```
- اگر `git status` تغییرات محلی نشان داد، پیش از pull آن‌ها را commit یا جداگانه پشتیبان‌گیری کنید؛ تغییرات را با دستور reset حذف نکنید.
- اگر قصد دارید دوباره Excel را وارد کنید، ابتدا مطمئن شوید فایل درست است. ورود مجدد، داده‌های منبع Excel را به‌روزرسانی می‌کند؛ بااین‌حال قبل از استفاده واقعی، رفتار آن را روی نسخه پشتیبان بررسی کنید.

## آزمون ۱ — برنامه روزانه، عملکرد فیزیکی و داشبورد
1. از صفحه «برنامه اجرایی» یک فعالیت موجود انتخاب کنید و شرح، حجم کل، واحد، عملکرد کل بازه، مانده و پیشرفت فعلی را یادداشت کنید.
2. در «برنامه اجرایی» روی «مدیریت برنامه روزانه» بزنید. برای یک تاریخ خالی مقدار برنامه‌ای با همان واحد فعالیت اضافه کنید؛ بررسی کنید برنامه Excel قابل بازنویسی یا حذف نباشد.
3. بررسی کنید مقدار «برنامه کل بازه» و تحقق/انحراف بعد از تغییر برنامه دستی به‌روزرسانی شوند.
4. به «پیشرفت فیزیکی» بروید، همان فعالیت را انتخاب و «ثبت عملکرد روزانه» را بزنید.
3. یک تاریخ شمسی که برای همان فعالیت هنوز رکورد ندارد و یک مقدار آزمایشی کوچک وارد کنید. از مقدار واقعی کارگاه استفاده نکنید مگر آن‌که قصد ثبت رسمی داشته باشید.
4. بررسی کنید عملکرد تجمعی به مقدار ثبت‌شده اضافه شود، مانده کاهش یابد و درصد پیشرفت تغییر کند.
5. به داشبورد برگردید. «پیشرفت وزنی فعالیت‌ها» باید پس از ثبت عملکرد تغییر کند، مشروط به این‌که فعالیت مبنای درآمدی Excel داشته باشد. شاخص مرجع Excel جداگانه باقی می‌ماند و الزاماً برابر نیست.
6. برای همان فعالیت و همان تاریخ دوباره «ثبت عملکرد روزانه» را بزنید. سیستم باید رکورد تکراری را رد کند و مقدار قبلی را بی‌صدا بازنویسی نکند.
7. از «ویرایش عملکرد روزانه» همان رکورد را انتخاب کنید و مقدارش را اصلاح کنید؛ سپس مانده و پیشرفت را دوباره کنترل کنید.

## آزمون ۲ — ورود فعالیت جدید
1. در «برنامه اجرایی» گزینه «افزودن فعالیت» را بزنید.
2. موقعیت، جبهه کاری، شرح، حجم کل، واحد و در صورت اطلاع تاریخ‌ها و هدف تولید روزانه را وارد کنید.
3. کنترل کنید تاریخ پایان پیش از شروع پذیرفته نشود و حجم کل صفر ذخیره نشود.
4. پس از ذخیره، مانده اولیه باید برابر حجم کل باشد. عملکرد واقعی را از صفحه «پیشرفت فیزیکی» ثبت کنید، نه از فرم تعریف فعالیت.
5. یک پیش‌نیاز آزمایشی تعریف و تحلیل مسیر بحرانی را اجرا کنید. این تحلیل جدا از موتور پیش‌بینی عادی است؛ تاریخ‌های دو بخش ممکن است متفاوت باشند.

## آزمون ۳ — دفتر مالی و پوشش هزینه
1. یک رکورد آزمایشی درآمد یا هزینه با تاریخ، مبلغ و فعالیت مرتبط ثبت کنید.
2. یک هزینه را به‌عنوان «پیش‌بینی‌نشده» علامت بزنید.
3. کارت‌های «درآمد/هزینه ثبت‌شده دستی» داشبورد و جدول «پوشش هزینه در سطح فعالیت» را کنترل کنید.
4. اگر فعالیت بودجه پایه ندارد، سیستم نباید برآورد عددی قطعی برای آن جعل کند. اگر دفتر مالی همه هزینه‌های پروژه را پوشش نمی‌دهد، هزینه ثبت‌شده را هزینه واقعی کامل پروژه تلقی نکنید.

## آزمون ۴ — فیلترها و ورود مجدد Excel
1. در صفحات «برنامه اجرایی» و «پیشرفت فیزیکی» فیلتر موقعیت، فعالیت و جستجوی متن را جداگانه امتحان کنید.
2. بعد از تغییر فیلتر، مقدارهای ثبت‌شده و تاریخ‌های فعالیت نباید تغییر کنند.
3. فقط روی نسخه پشتیبان، فایل Excel را دوباره وارد کنید.
4. بررسی کنید عملکردهای دستی، رکوردهای مالی دستی، فعالیت‌های دستی و ریسک‌های دستی باقی بمانند؛ داده‌های Excel باید از فایل منبع تازه‌سازی شوند.
5. در گزارش مغایرت‌ها، خطای فرمول Excel و ردیف‌های پیشرفت فیزیکی بدون تطبیق را بررسی کنید.

## نتیجه را ثبت کنید
برای هر مورد بنویسید: «قبول»، «رد» یا «قابل بررسی نیست». اگر نتیجه غیرمنتظره بود، از صفحه عکس بگیرید و خطای کامل ترمینال را بفرستید. تا وقتی آزمون‌ها تمام نشده‌اند، فایل اصلی دیتابیس را تنها نسخه داده‌های خود قرار ندهید.
