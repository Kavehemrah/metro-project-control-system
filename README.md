# Metro Project Control System

سیستم کنترل پروژه مترو بر پایه Python + PySide6 + SQLite، با هدف تبدیل منطق فایل Excel پروژه به یک مدل واقعی کنترل پروژه.

## منطق اصلی

مدل نرم‌افزار بر اساس زنجیره واقعی فایل پروژه ساخته شده است:

برنامه عملیاتی → پیشرفت فیزیکی → درآمد → هزینه → بالانس مالی

و در کنار آن:

برنامه → منابع / ماشین‌آلات / نیروی انسانی / مصالح

ریسک → اقدام اصلاحی

پیشرفت فعالیت از روی عملکرد واقعی محاسبه می‌شود و یک مقدار دستی و مستقل نیست.

## مدل برنامه و پیشرفت

هر فعالیت دارای اطلاعات پایه زیر است:
- موقعیت
- جبهه کاری
- شرح فعالیت
- حجم کل
- مانده برنامه عملیاتی
- مانده فیزیکی براساس پیشرفت
- عملکرد مبنا از شیت Excel
- عملکرد دستی روزانه
- واحد
- شروع / پایان
- مدت
- برنامه روزانه
- برنامه دوره
- عملکرد واقعی
- پیشرفت
- تأخیر
- وضعیت

برای کنترل واقعی، دو سطح ثبت عملکرد وجود دارد:
- activity_daily_plan: برنامه روزانه
- activity_daily_actual: عملکرد واقعی روزانه
- activity_period: برنامه/عملکرد دوره‌ای مطابق شیت پیشرفت فیزیکی

بنابراین کنترل اصلی به صورت Planned / Actual / Variance / Achievement انجام می‌شود. عملکرد مبنا و عملکرد دستی جدا نگهداری می‌شوند و ثبت روزانه، baseline واردشده از Excel را بازنویسی نمی‌کند. KPI کل پیشرفت فیزیکی از مقدار وزنی شیت Excel خوانده می‌شود؛ واحدهای ناهمگون فعالیت‌ها با هم جمع نمی‌شوند.

## Excel Import

فایل اصلی پروژه در ریشه مخزن قرار دارد:
metro-project-control-system.xlsx

Import فعلی این بخش‌ها را از Excel می‌خواند:
- اطلاعات پروژه و دوره گزارش
- KPI و درآمد/هزینه خلاصه
- شیت «برنامه عملیاتی»
- شیت «پيشرفت فيزيكي»
- برنامه روزانه در صورت وجود تاریخ در سربرگ ستون‌ها
- عملکرد دوره‌ای و مقدار تجمعی
- هزینه تفصیلی برای کنترل مغایرت با خلاصه
- موقعیت، جبهه، شرح، حجم کل، عملکرد مبنا، عملکرد ماهانه و مانده فیزیکی
- نیاز ماهانه ماشین‌آلات، نیروی انسانی و مصالح؛ بهای واحد و نیاز خرید مصالح
- مبلغ قرارداد و ریسک‌های شیت پروژه
- فرمول‌های دارای #REF!

مغایرت‌های کشف‌شده به جدول discrepancy وارد می‌شوند تا در داشبورد قابل کنترل باشند.
داده‌های Excel با منبع `EXCEL` و ورودی‌های دستی با منبع `MANUAL` مشخص می‌شوند. ورود مجدد، رکوردهای Excel را به‌روزرسانی می‌کند و داده‌های دستی و عملکرد روزانه را حذف نمی‌کند. فعالیت‌های قدیمی که در فایل جدید نیستند برای حفظ تاریخچه نگه داشته می‌شوند و به‌صورت مغایرت گزارش می‌شوند.

## کنترل مالی

درآمد، هزینه و بالانس به صورت جداگانه نگهداری می‌شوند. اختلاف هزینه خلاصه و هزینه تفصیلی نیز به عنوان مغایرت کنترل می‌شود؛ بنابراین اختلاف شناخته‌شده حدود 12.33 میلیارد ریال در فایل Excel نباید در نرم‌افزار پنهان شود.

## اجرا

```bash
python -m pip install -r requirements.txt
python main.py
```

برای نصب وابستگی تست و اجرای تست‌های ایزوله:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

ورود دستی Excel:

```bash
python -m imports.import_excel "metro-project-control-system.xlsx"
```

## موتور زمان‌بندی و پیش‌بینی

ماژول `app/services/forecast.py` موارد زیر را انجام می‌دهد:
- محاسبه تاریخ پایان پیش‌بینی از عملکرد ثبت‌شده و نرخ متوسط تولید؛ در نبود عملکرد، از پایان مبنا استفاده می‌شود.
- انتقال تأخیر از پیش‌نیاز به فعالیت‌های بعدی با روابط FS، SS، FF و SF و وقفه تقویمی.
- تشخیص چرخه در وابستگی‌ها؛ در صورت وجود چرخه، برنامه ناقص ذخیره نمی‌شود.
- نمایش پایان پیش‌بینی و تأخیر محاسبه‌شده در فهرست فعالیت‌ها.
- مدیریت دستی پیش‌نیازها از صفحه فعالیت‌ها، با روابط FS/SS/FF/SF و وقفه روز تقویمی.

تمام محاسبات زمان‌بندی در حال حاضر بر اساس روز تقویمی است؛ تقویم کاری، تعطیلات، مسیر بحرانی و منابع محدودشده هنوز مدل نشده‌اند. وابستگی‌های استنباط‌شده از ترتیب ردیف‌ها و جبهه کاری باید توسط برنامه‌ریز بررسی شوند.

## دفتر مالی واقعی و برآورد هزینه

- دفتر واقعی از بودجه‌های Excel و ریز هزینه پایه جداست و برای ثبت درآمد واقعی یا هزینه‌های اضافه/پیش‌بینی‌نشده، همراه با تاریخ، شرح، مبلغ و فعالیت مرتبط استفاده می‌شود. ثبت روزانه تمام هزینه‌های عادی الزامی نیست.
- برآورد هزینه هر فعالیت از ریز هزینه واحدمحور محاسبه می‌شود؛ هزینه‌های غیرمنتظره که به‌عنوان «پیش‌بینی‌نشده» علامت‌گذاری شده‌اند به برآورد مبنا اضافه می‌شوند.
- برآورد فعلی فقط جمع فعالیت‌هایی را شامل می‌شود که بودجه واحدمحور یا بودجه هزینه تخصیص‌یافته دارند. فعالیت‌های فاقد برآورد پایه جداگانه شمرده می‌شوند؛ عدد برآورد شده را نباید بدون پوشش کامل فعالیت‌ها، برآورد کل قطعی پروژه تلقی کرد.
- CPI و هزینه باقی‌مانده نمایش داده نمی‌شوند، چون دفتر واقعی می‌تواند فقط استثناها و هزینه‌های اضافه را در بر بگیرد و لزوماً هزینه عادی تجمعی و کامل پروژه را ثبت نمی‌کند. این دو شاخص وقتی قابل اتکا می‌شوند که هزینه واقعی جامع و تعهدات هزینه‌ای نیز در مدل ثبت شوند.
- درآمد واقعی، هزینه واقعی ثبت‌شده و خالص آن‌ها جدا گزارش می‌شوند و خلاصه‌های Excel با ردیف‌های فعالیتی دوباره جمع نمی‌شوند. هزینه‌ها یا درآمدهای بدون تخصیص نیز جدا نمایش داده می‌شوند.
- صفحه مالی پوشش درآمد مبنای فعالیت‌ها نسبت به مبلغ قرارداد ثبت‌شده در Excel را نشان می‌دهد: جمع درآمد متصل به فعالیت‌ها، درصد پوشش و فاصله تا مبلغ قرارداد. این فقط شاخص پوشش مدل است، نه تأیید صورت‌وضعیت یا مبلغ قابل وصول.
- برآورد هزینه پایه فعالیت‌ها در کنار جمع مرجع هزینه دوره‌ای Excel نمایش داده می‌شود. چون این دو عدد ممکن است دامنه یا دوره زمانی متفاوت داشته باشند، اختلاف آن‌ها برای بررسی گزارش می‌شود و به‌تنهایی اثبات‌کننده خطا نیست.
- ردیف‌های ریزهزینه با ضریب یا بهای واحد صفر هشدار می‌گیرند؛ چنین ردیف‌هایی نباید به‌عنوان پوشش هزینه معتبر فرض شوند.

## پوشش هزینه در سطح فعالیت

- صفحه مالی برای هر فعالیت، منبع بودجه پایه را جدا نشان می‌دهد: ریزهزینه واحدمحور، بودجه هزینه تخصیص‌یافته، یا فاقد بودجه پایه.
- ارزش کسب‌شده هزینه‌ای هر فعالیت از بودجه پایه همان فعالیت × درصد پیشرفت فیزیکی محاسبه می‌شود؛ این شاخص با هزینه واقعی ثبت‌شده یکی نیست.
- هزینه واقعی ثبت‌شده و هزینه پیش‌بینی‌نشده در سطح فعالیت جدا نمایش داده می‌شوند. دفتر واقعی ممکن است فقط هزینه‌های استثنایی یا تجمیعی را داشته باشد؛ بنابراین از آن به‌تنهایی برای CPI یا هزینه واقعی کامل پروژه استفاده نمی‌شود.
- برآورد قابل ارزیابی هر فعالیت برابر بودجه پایه به‌علاوه هزینه‌های پیش‌بینی‌نشده ثبت‌شده در همان فعالیت است. برای فعالیت فاقد بودجه پایه، برآورد عددی نمایش داده نمی‌شود تا هزینه واقعی ثبت‌شده به‌اشتباه جایگزین برآورد کل تلقی نشود.
- ردیف‌های ریزهزینه با ضریب یا بهای واحد صفر/نامعتبر در جدول پوشش هزینه هشدار می‌گیرند و باید بررسی شوند.

## هزینه واحدمحور فعالیت‌ها و ظرفیت منابع

- در صفحه «برآورد هزینه و منابع فعالیت» برای هر فعالیت ریز هزینه پایه تعریف می‌شود: مصالح، ماشین‌آلات، پیمانکار، نیروی انسانی و سایر اقلام. برآورد کل هر خط = مقدار مصرف به ازای یک واحد فعالیت × بهای واحد × حجم کل فعالیت.
- هزینه‌های عادی و تکراری لازم نیست هر روز ثبت شوند؛ تعریف بهای واحد و ضرایب، برآورد مبنا را می‌سازد. موارد اضافه مانند استفاده خارج از برنامه از لودر، در دفتر واقعی با علامت «هزینه پیش‌بینی‌نشده» و فعالیت مرتبط ثبت می‌شوند.
- برای هر فعالیت می‌توان ضرایب نیاز نیروی انسانی، ماشین‌آلات و مصالح را به ازای یک واحد خروجی تعریف کرد. نیاز مصالح طی دوره جمع می‌شود؛ نیروی انسانی و ماشین‌آلات براساس اوج مقدار تولید روزانه برنامه‌ریزی‌شده سنجیده می‌شوند. اگر برای ظرفیت روزانه برنامه یا راندمان مبنا وجود نداشته باشد، سیستم کمبود نیروی انسانی/ماشین‌آلات را حدس نمی‌زند و «نامشخص» نشان می‌دهد.
- صفحه‌های «برنامه اجرایی» و «پیشرفت فیزیکی» فیلتر موقعیت، فیلتر فعالیت و جستجوی متن دارند.
- در ورود Excel، ستون «بهای واحد درآمد» و حجم کل شیت پیشرفت فیزیکی برای ساختن مبلغ پایه درآمد فعالیت استفاده می‌شوند. ردیف‌های درآمد خلاصه Excel به‌عنوان مرجع تطبیق نگه داشته می‌شوند و با جمع درآمد فعالیت‌ها دوباره جمع نمی‌شوند. اختلاف جمع درآمد خلاصه با جمع نرخ‌های فعالیت گزارش می‌شود؛ منبع اصلی، نرخ و احجام ثبت‌شده در همان workbook است.
- تاریخ‌ها در بانک اطلاعاتی به قالب استاندارد میلادی ISO نگه‌داری می‌شوند تا محاسبات و مرتب‌سازی پایدار باشد، اما ورودی و نمایش رابط کاربری شمسی است.

## پیش‌بینی مالی و کمبود منابع

- درآمد فعالیتی از نرخ واحد و حجم کل خوانده‌شده از شیت پیشرفت فیزیکی Excel به هر فعالیت قابل تطبیق متصل می‌شود؛ ردیف‌های خلاصه Excel به‌عنوان مرجع جدا باقی می‌مانند.
- مبالغ مالی بدون تخصیص فعالیت جداگانه گزارش می‌شوند؛ سیستم آن‌ها را به فعالیت‌ها نسبت نمی‌دهد.
- در صفحه هزینه و منابع فعالیت، نیاز هر منبع بر اساس ضریب مصرف به ازای واحد خروجی محاسبه می‌شود. نیاز مصالح در دوره جمع می‌شود و موجودی کلی مصالح در صورت نبود برنامه تأمین دوره‌ای بین دوره‌ها منتقل می‌شود؛ نیروی انسانی و ماشین‌آلات با اوج نیاز روزانه مقایسه می‌شوند.
- هزینه تخمینی کمبود منابع فقط در صورت وجود بهای واحد نمایش داده می‌شود. نبود برنامه روزانه برای ظرفیت نیروی انسانی/ماشین‌آلات به‌جای عدد ساختگی، «نامشخص» ایجاد می‌کند.

برآورد هزینه کل پروژه زمانی کامل‌تر می‌شود که برای فعالیت‌های اصلی ریزهزینه واحدمحور تعریف و پوشش بودجه بررسی شود. هزینه عادی روزانه ثبت نمی‌شود؛ موارد خارج از مبنا باید به‌عنوان هزینه پیش‌بینی‌نشده ثبت شوند.

## تقویم کاری و مسیر بحرانی

- سرویس مستقل app/services/schedule_analysis.py تقویم کاری و تحلیل مسیر بحرانی (CPM) را بدون تغییر دادن تاریخ‌های موتور پیش‌بینی فعلی محاسبه می‌کند.
- روابط FS، SS، FF و SF و وقفه بر حسب روز کاری پشتیبانی می‌شوند؛ چرخه وابستگی‌ها به‌عنوان خطا گزارش می‌شود.
- تقویم پیش‌فرض شنبه تا پنج‌شنبه کاری و جمعه تعطیل است. تعطیلات به تفکیک پروژه در جدول `calendar_holiday` ذخیره می‌شوند و از صفحه برنامه اجرایی یا پیشرفت فیزیکی با دکمه «مدیریت تعطیلات» قابل ثبت، ویرایش و حذف هستند.
- تاریخ تعطیلات در دیتابیس به قالب میلادی ISO ذخیره و در رابط کاربری شمسی نمایش داده می‌شود؛ برای هر پروژه، ثبت دو تعطیلی در یک تاریخ مجاز نیست.
- در صفحه برنامه اجرایی و پیشرفت فیزیکی، دکمه «تحلیل مسیر بحرانی» مدت محاسباتی، فعالیت‌های بحرانی و تاریخ‌های زودترین شروع/پایان را با لحاظ تعطیلات ثبت‌شده نمایش می‌دهد. این تحلیل فقط خواندنی است و تاریخ‌های ذخیره‌شده یا موتور پیش‌بینی فعلی را تغییر نمی‌دهد.
- این تحلیل بر اساس مدت فعالیت و روابط تعریف‌شده است؛ تا زمانی که پیش‌نیازهای واقعی و مدت فعالیت‌ها بازبینی نشده‌اند، خروجی نباید برنامه مصوب تلقی شود.

## وضعیت توسعه

شاخه فعلی برای توسعه منطق کنترل پروژه استفاده می‌شود و هنوز نباید به main merge شود.

مرحله بعدی توسعه:
1. افزودن مدیریت تعطیلات و امکان تعریف تقویم متفاوت برای جبهه‌ها یا پیمانکاران
2. تکمیل نیاز ظرفیت روزانه و هم‌زمانی ماشین‌آلات/گروه‌های نیروی انسانی
3. سناریوهای What-if برای تغییر راندمان، منابع و تاریخ‌های شروع
4. تکمیل داشبورد مدیریتی نهایی و اعتبارسنجی روی فایل واقعی پروژه
